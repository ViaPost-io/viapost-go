# Migrating to v0.4.0

This guide records the public Go API changes between the last tagged release before v0.4.0,
`v0.2.0`, and `v0.4.0`. The repository has release notes headed `v0.3.0`, but no `v0.3.0` Git
tag was published; use this guide when upgrading from either the v0.2.0 tag or an untagged build
containing those notes.

The ergonomic `viapost` services did not gain a segments facade in this release. The changes below
apply to the generated, low-level `github.com/ViaPost-io/viapost-go/api` package returned by
`client.Raw()`.

## Required source changes

### Create segments with a value and raw JSON fields

`(*api.Client).PostSegments` and `api.Invoker.PostSegments` now take an
`api.CreateSegmentRequest` value. `CreateSegmentRequest` is a
`map[string]jx.Raw`, rather than a struct with `Name` and `Description` fields. The same raw-map
representation is used by response `api.Segment` and `api.SegmentDefinition` because the public
contract contains recursive `oneOf` JSON objects.

```go
// v0.2.0
request := &api.CreateSegmentRequest{Name: "VIP customers"}
response, err := client.Raw().PostSegments(ctx, request)

// v0.4.0
request := api.CreateSegmentRequest{
	"name": jx.Raw(`"VIP customers"`),
}
response, err := client.Raw().PostSegments(ctx, request)
```

For a dynamic segment, encode `kind` and `definition` as JSON too:

```go
request := api.CreateSegmentRequest{
	"name":       jx.Raw(`"Recent purchasers"`),
	"kind":       jx.Raw(`"dynamic"`),
	"definition": jx.Raw(`{"all":[{"event_name":"purchase.completed","operator":"occurred","within_days":30}]}`),
}
```

Use `request.Validate()` before sending when constructing these maps outside the generated request
path. A static request omits `definition`; a dynamic request requires it. `Segment.Validate()`
validates a received raw-map segment. Decode individual raw fields with `encoding/json` rather than
selecting former struct fields.

### Convert contact timestamps explicitly

`api.Contact.CreatedAt` and `UpdatedAt` changed from `api.Timestamp` to
`api.SegmentTimestamp`. Both have `time.Time` as their underlying representation, but they are
different named Go types. Update typed assignments and function arguments with an explicit
conversion:

```go
created := time.Time(contact.CreatedAt)
contact.CreatedAt = api.SegmentTimestamp(created)
```

### Treat list cursors as empty-or-next strings

`api.ContactList.NextCursor` and `api.SegmentList.NextCursor` (and their getters/setters) changed
from `api.OptString` to `string`. An empty string means there is no next page; a non-empty value is
opaque and must be passed back unchanged.

```go
if page.NextCursor != "" {
	params.Cursor = api.NewOptString(page.NextCursor)
}
```

The request parameters remain optional `api.OptString` values. Do not parse, synthesize, or modify
the returned cursor, and reuse it only with the same filters.

### Use the generated message status types

`api.Message.Status` is now `api.MessageStatus`, and `api.MessageDetail.Status` is now
`api.MessageDetailStatus`. Replace typed `string` variables or function arguments with the
corresponding status type, or convert with `string(status)` at a string-only boundary. The generated
constants include `Scheduled`, `Queued`, `Processing`, `Sent`, `Delivered`, `Deferred`, `Bounced`,
`Failed`, `Suppressed`, `Rejected`, `Cancelled`, and `Complained` for each type.

```go
if message.Status == api.MessageStatusDelivered {
	// ...
}
label := string(message.Status)
```

### Use a string for dynamic-segment membership error codes

`api.DynamicSegmentMembershipErrorError.Code` (and its getter and setter) changed from
`jx.Raw` to `string`. Code that constructed or compared the raw JSON value must now use the
ordinary string value:

```go
// Build containing the v0.3.0 release notes
detail.Code = jx.Raw(`"dynamic_segment"`)

// v0.4.0
detail.Code = "dynamic_segment"
```

### Read webhook secrets through the explicit accessor

`CreateWebhookResult.Secret` is no longer an exported field. Use
`result.Secret()` to retrieve the one-time value, then store it in your secret manager. Formatting,
`slog`, and JSON serialization redact this value by design.

```go
created, err := client.Webhooks.Create(ctx, endpoint, events)
if err != nil {
	return err
}
storeSecret(created.Secret())
```

## Generated response compatibility

The public OpenAPI contract removed these generated response types. Stop type-asserting them; use
the response types still declared by the operation (or handle the returned API error) instead:

- `api.DeleteContactsIDConflict`, `api.DeleteSegmentsIDConflict`, and
  `api.DeleteSegmentsIDContactsContactIDConflict`
- `api.GetContactsConflict`, `api.GetContactsIDConflict`, and `api.GetContactsNotFound`
- `api.GetSegmentsConflict`, `api.GetSegmentsIDConflict`, `api.GetSegmentsIDContactsConflict`,
  `api.GetSegmentsIDContactsNoContent`, and `api.GetSegmentsNotFound`
- `api.PostContactsNotFound`, `api.PostSegmentsIDContactsConflict`, and
  `api.PostSegmentsNotFound`

`api.ErrorDetail` now includes a slice of validation details. Consequently, `api.Error`,
`api.TooManyRequestsHeaders`, `api.UpdateSegmentRequest`, and generated response-error aliases
that embed `api.Error` are no longer comparable. Replace `==`, `!=`, and map-key use of those
values with an explicit comparison of the fields relevant to the application; continue to use
`errors.As` for returned errors.

## Newly generated low-level operations

The following public operations were added to `api.Client` and `api.Invoker`. If your code provides
a custom `api.Invoker`, implement them before upgrading:

- contacts import: `PostContactsImport`
- tracking domains: `GetDomainTrackingDomain`, `GetDomainTrackingDomains`,
  `PostDomainTrackingDomains`, `PostDomainTrackingDomainActivate`,
  `PostDomainTrackingDomainProofRotate`, `PostDomainTrackingDomainRevoke`, and
  `PostDomainTrackingDomainVerify`
- domain health and inbound configuration: `GetDomainsIDHealth`, `GetDomainsIDInbound`
- outbound event feed and cancellation: `GetMessagesEvents`, `PostMessagesIDCancel`
- segments preview: `PostSegmentsPreview`
- batch email send: `PostSendBatch`

## Upgrade check

After updating call sites, run:

```bash
go get github.com/ViaPost-io/viapost-go@v0.4.0
go test ./...
```

`make api-diff` in this repository compares the public Go surface to the previous published tag;
it is the source used for the compatibility inventory above.
